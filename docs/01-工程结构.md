# 01 工程结构

## 1. Maven 模块划分

五个模块，依赖单向向下，不允许反向或循环依赖。

```
flash-sale-system                       (pom, 父工程，统一依赖版本)
├── fss-common                          (jar) 零业务依赖
│   ├── 统一响应体 R<T> / PageR<T>
│   ├── 错误码枚举 ErrorCode
│   ├── 业务异常 BizException
│   ├── 全局异常处理 GlobalExceptionHandler
│   ├── 工具类 IdGenerator / JsonUtil / IpUtil
│   └── 常量与枚举（订单状态、请求状态、消息类型）
│
├── fss-infra                           (jar) 依赖 common
│   ├── Redis 配置 + RedisTemplate 定制序列化
│   ├── Lua 脚本加载器 SeckillScriptLoader
│   ├── RocketMQ 生产者封装 ReliableMqProducer
│   ├── MyBatis-Plus 配置 + 分页插件 + 自动填充
│   ├── 分布式锁 DistributedLock (Redisson)
│   └── 链路追踪 TraceIdFilter + MDC
│
├── fss-domain                          (jar) 依赖 common
│   ├── entity/       与表一一对应的实体
│   ├── mapper/       MyBatis-Plus Mapper 接口 + XML
│   ├── dto/          内部传输对象
│   └── message/      MQ 消息体定义
│
├── fss-biz                             (jar) 依赖 domain + infra
│   ├── user/         用户与认证
│   ├── product/      商品与 SKU
│   ├── activity/     活动管理与预热
│   ├── seckill/      秒杀核心（高并发入口）
│   ├── order/        订单与状态机
│   ├── payment/      模拟支付
│   ├── reconcile/    补偿与对账
│   ├── consumer/     MQ 监听器
│   └── job/          定时任务
│
└── fss-app                             (jar, 可执行) 依赖 biz
    ├── controller/   REST 接口层
    ├── config/       Web / Security / Sentinel / OpenAPI 配置
    ├── interceptor/  JWT 认证、限流拦截器
    └── FssApplication.java
```

**为什么 domain 不依赖 infra**：实体与 Mapper 是纯数据契约，让 domain 独立可以在
单元测试中直接构造实体而不启动 Redis/MQ 上下文。

**为什么 biz 里按业务分包而非分模块**：七个业务域各自建 Maven 模块会产生 12 个
模块和大量跨模块接口下沉，对本项目规模是负收益。分包已足够表达边界；包之间
只允许通过 `XxxService` 接口调用，禁止跨包直接用别人的 Mapper。

## 2. fss-biz 内部包结构（以 seckill 为例）

```
com.fss.biz.seckill
├── service
│   ├── SeckillService.java             对外接口
│   └── impl/SeckillServiceImpl.java
├── core
│   ├── SeckillExecutor.java            Redis Lua 执行封装
│   ├── SeckillTokenService.java        秒杀令牌签发与校验
│   └── SeckillResultService.java       请求结果读写
├── model
│   ├── SeckillCmd.java                 入参命令对象
│   └── SeckillResult.java              出参
└── converter/SeckillConverter.java     MapStruct 转换
```

同样结构复制到 order / activity / payment。`consumer` 与 `job` 包只做编排，
不写业务规则，规则都在各业务包的 Service 里。

## 3. 三种运行角色

同一个 jar，用 Spring Profile 控制 Bean 装配。

```java
// fss-biz/consumer/OrderCreateListener.java
@Profile("consumer")
@RocketMQMessageListener(
        topic = "${fss.mq.topic.order-create}",
        consumerGroup = "${fss.mq.group.order-create}",
        consumeThreadNumber = 20,
        maxReconsumeTimes = 5)
@Component
public class OrderCreateListener implements RocketMQListener<OrderCreateMessage> { ... }
```

```java
// fss-biz/job/ReconcileJob.java
@Profile("job")
@Component
public class ReconcileJob { ... }
```

```java
// fss-app/controller/SeckillController.java
@Profile("web")
@RestController
@RequestMapping("/api/seckill")
public class SeckillController { ... }
```

启动命令：

```bash
# Web 层，2 实例
java -jar fss-app.jar --spring.profiles.active=web,prod --server.port=8080
# 消费层，2 实例
java -jar fss-app.jar --spring.profiles.active=consumer,prod --server.port=8090
# 任务层，1 实例（或多实例 + Redisson 锁）
java -jar fss-app.jar --spring.profiles.active=job,prod --server.port=8099
```

本地开发用 `--spring.profiles.active=web,consumer,job,dev` 一把起全部。

**job 单实例的兜底**：即使部署成多实例，每个定时方法都套 `@DistributedLock`，
Redisson 抢不到锁直接返回，因此多实例只是浪费一次 Redis 请求，不会重复执行。

```java
@Scheduled(cron = "0 */1 * * * ?")
@DistributedLock(key = "job:mq-resend", waitTime = 0, leaseTime = 50)
public void resendPendingMessages() { ... }
```

## 4. 父 POM 依赖管理

```xml
<properties>
    <java.version>17</java.version>
    <spring-boot.version>3.3.5</spring-boot.version>
    <mybatis-plus.version>3.5.9</mybatis-plus.version>
    <rocketmq-spring.version>2.3.1</rocketmq-spring.version>
    <redisson.version>3.36.0</redisson.version>
    <sentinel.version>1.8.8</sentinel.version>
    <springdoc.version>2.6.0</springdoc.version>
    <mapstruct.version>1.6.2</mapstruct.version>
    <testcontainers.version>1.20.3</testcontainers.version>
</properties>
```

注意点：

- Spring Boot 3.x 的基线就是 JDK 17，本项目未使用虚拟线程等 21 特性，故按 17 落地。
- **MyBatis-Plus 3.5.9 起把 JSqlParser 从核心包剥离**，`PaginationInnerInterceptor`
  依赖它，必须额外引入 `mybatis-plus-jsqlparser`，否则编译期就找不到类。
- RocketMQ 5.x broker 配合 `rocketmq-spring-boot-starter` 2.3.1 客户端，
  定时消息需 broker 开启 `timerWheelEnable=true`。
- Spring Boot 3.x 起 `javax.*` 全部换成 `jakarta.*`，JWT 库选 `jjwt 0.12.x`。
- MyBatis-Plus 3.5.9 才完整支持 Spring Boot 3，需引 `mybatis-plus-spring-boot3-starter`。

## 5. 核心配置项

`application.yml` 中与业务语义相关的自定义配置，全部集中在 `fss` 前缀下并绑定到
`@ConfigurationProperties(prefix = "fss")` 的 `FssProperties`，不散落在代码里。

```yaml
fss:
  order:
    pay-timeout: 15m              # 决策 3：关单时长，不受 MQ 延迟级别约束
    close-scan-delay: 2m          # 定时扫描时，超过 pay-timeout + 该值才处理
  seckill:
    result-ttl: 30m               # 秒杀请求结果在 Redis 的保留时长
    token-ttl: 5m                 # 秒杀令牌有效期
    warmup-ahead: 5m              # 活动开始前多久预热
    cache-ttl: 2h                 # 活动/商品缓存基础 TTL
    cache-ttl-jitter: 10m         # 随机抖动上限，防雪崩
    null-cache-ttl: 60s           # 空值缓存，防穿透
    allow-repurchase-after-cancel: false   # 决策 1，硬编码为 false，留配置以示意
  ratelimit:
    user-qps: 2                   # 单用户每秒秒杀请求数
    ip-qps: 20                    # 单 IP 每秒秒杀请求数
    activity-qps: 5000            # 单活动每秒放行上限
    global-qps: 12000
  mq:
    topic:
      order-create: FSS_ORDER_CREATE
      order-close: FSS_ORDER_CLOSE
      stock-release: FSS_STOCK_RELEASE
      stock-rollback: FSS_STOCK_ROLLBACK
    group:
      order-create: GID_FSS_ORDER_CREATE
      order-close: GID_FSS_ORDER_CLOSE
      stock-release: GID_FSS_STOCK_RELEASE
      stock-rollback: GID_FSS_STOCK_ROLLBACK
    send-timeout: 2000
    max-resend: 5
  degrade:
    seckill-enabled: true         # 总开关，可运行时关闭秒杀入口
    backlog-threshold: 50000      # 消息积压超过该值自动暂停资格分配
```

`allow-repurchase-after-cancel` 保留为配置项但代码中断言必须为 `false`，
启动时校验，避免有人误开导致 [决策 1](00-设计总览.md#决策-1一人一单的最终归属与取消语义) 描述的死循环。

## 6. 数据源与连接池

```yaml
spring:
  datasource:
    type: com.zaxxer.hikari.HikariDataSource
    hikari:
      maximum-pool-size: 30       # 消费端 20 线程 + 定时任务 + 余量
      minimum-idle: 10
      connection-timeout: 3000    # 快速失败，不让请求堆在获取连接上
      max-lifetime: 1740000
  data:
    redis:
      lettuce:
        pool:
          max-active: 200         # Web 层高并发，池要够
          max-idle: 50
          min-idle: 20
      timeout: 500ms              # 秒杀链路必须快速失败
```

Web 角色的 `maximum-pool-size` 可降到 10（只有本地消息表写入用 DB），
消费角色保持 30。通过 profile 覆盖：`application-web.yml` / `application-consumer.yml`。
